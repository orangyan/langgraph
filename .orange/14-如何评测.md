# 14 如何评测

## LangGraph 的测试策略

LangGraph 是基础框架，测试重点在**引擎正确性**（Channels、Checkpointer、Pregel 超步）而非 Agent 行为。

---

## 14.1 测试体系概览

```
LangGraph 测试分层:
┌────────────────────────────────────────────┐
│  集成测试: 实际 LLM 调用（需 API key）       │  ← 少量，成本高
└────────────────────────────────────────────┘
┌────────────────────────────────────────────┐
│  组件测试: 图执行、Channel 行为、Checkpointer │  ← 主要测试
└────────────────────────────────────────────┘
┌────────────────────────────────────────────┐
│  单元测试: Channel 逻辑、序列化、工具函数    │  ← 最基础
└────────────────────────────────────────────┘
```

## 14.2 Pregel 执行引擎测试

```python
# libs/langgraph/tests/test_pregel.py

def test_simple_graph():
    """测试基本图执行流程"""
    builder = StateGraph({"value": str})
    builder.add_node("node_a", lambda s: {"value": s["value"] + "a"})
    builder.add_node("node_b", lambda s: {"value": s["value"] + "b"})
    builder.add_edge(START, "node_a")
    builder.add_edge("node_a", "node_b")
    builder.add_edge("node_b", END)

    graph = builder.compile()
    result = graph.invoke({"value": "start"})
    assert result["value"] == "startab"

def test_parallel_execution():
    """测试同一超步内的并行节点执行"""
    # 两个节点都从 START 开始，应该在同一超步内并行执行
    builder = StateGraph({"values": list})
    builder.add_node("node_a", lambda s: {"values": s["values"] + ["a"]})
    builder.add_node("node_b", lambda s: {"values": s["values"] + ["b"]})
    builder.add_edge(START, "node_a")
    builder.add_edge(START, "node_b")

    graph = builder.compile()
    result = graph.invoke({"values": []})
    assert set(result["values"]) == {"a", "b"}  # 顺序不保证，但两个都有

def test_checkpoint_resume():
    """测试断点恢复"""
    checkpointer = InMemorySaver()
    graph = builder.compile(
        checkpointer=checkpointer,
        interrupt_before=["node_b"]
    )
    config = {"configurable": {"thread_id": "test-1"}}

    # 第一次执行，在 node_b 前中断
    graph.invoke(input, config=config)

    state = graph.get_state(config)
    assert state.next == ("node_b",)

    # 恢复执行
    result = graph.invoke(None, config=config)
    assert result  # 完成执行
```

def test_last_value():
    ch = LastValue(str)
    ch.update(["hello"])
    assert ch.get() == "hello"
    ch.update(["world"])
    assert ch.get() == "world"  # 覆盖

def test_binary_operator_aggregate():
    """add_messages 聚合函数测试"""
    ch = BinaryOperatorAggregate(list, operator.add)
    ch.update([["msg1"]])
    ch.update([["msg2"]])
    assert ch.get() == ["msg1", "msg2"]  # 追加，不覆盖

def test_ephemeral_value_clears():
    ch = EphemeralValue(str)
    ch.update(["temp_value"])
    assert ch.get() == "temp_value"
    ch.after_checkpoint()  # 超步结束
    assert ch.get() is None  # 自动清除

## 14.4 Checkpointer 测试

```python
# 使用 InMemorySaver 测试（不需要 PostgreSQL）
async def test_checkpoint_persistence():
    checkpointer = InMemorySaver()
    graph = build_test_graph(checkpointer)
    config = {"configurable": {"thread_id": "test-thread"}}

    # 第一轮
    await graph.ainvoke({"messages": [HumanMessage("Hello")]}, config=config)

    # 验证状态已保存
    state = graph.get_state(config)
    assert len(state.values["messages"]) > 0

    # 第二轮（应该包含第一轮的历史）
    result = await graph.ainvoke(
        {"messages": [HumanMessage("World")]},
        config=config
    )
    # 验证消息累积
    assert len(result["messages"]) >= 2
```

## 14.5 使用 Mock LLM 测试（不消耗 API 配额）

```python
from unittest.mock import MagicMock
from langchain_core.messages import AIMessage

def test_agent_calls_tools():
    """不需要真实 LLM 的 Agent 测试"""
    # Mock LLM：第一次返回工具调用，第二次返回最终回复
    mock_llm = MagicMock()
    mock_llm.invoke.side_effect = [
        AIMessage(
            content="",
            tool_calls=[{"name": "search", "id": "1", "args": {"query": "test"}}]
        ),
        AIMessage(content="The answer is X"),
    ]

    mock_search = MagicMock()
    mock_search.name = "search"
    mock_search.invoke.return_value = "Search result: X"

    graph = build_react_graph(mock_llm, [mock_search])
    result = graph.invoke({"messages": [HumanMessage("What is X?")]})

    # 验证工具被调用了
    mock_search.invoke.assert_called_once()
    assert "X" in result["messages"][-1].content
```

## 14.6 与其他项目的评测体系对比

| 维度 | LangGraph | deer-flow | hermes-agent | nanobot | gstack |
|------|---------|-----------|--------------|---------|--------|
| **测试框架** | pytest + pytest-asyncio | pytest + pytest-asyncio | pytest + Atropos | pytest | bun test + LLM judge |
| **测试类型** | 引擎正确性为主 | 组件行为正确性 | 任务完成率 benchmark | 代码正确性 | 技能行为 + 文档质量 |
| **Mock LLM** | ✅ (MagicMock) | ✅ | ❌ (真实 LLM) | ❌ | ❌ (真实 LLM) |

## 14.7 LangGraph 的测试哲学

LangGraph 作为**基础框架**，测试重点在：
1. **引擎行为正确性**: Pregel 超步、Channel 聚合、Checkpoint 序列化
2. **边界条件**: 并发节点、中断恢复、子图嵌套
3. **性能**: 大量节点的超步规划性能

不做 Agent 行为测试（那是使用者的责任），也不做 LLM 质量评估（那是模型提供商的责任）。

这与 hermes-agent（深度 benchmark）和 gstack（LLM judge 质量评估）形成对比：
- LangGraph: 框架正确性 → 用 Mock LLM
- hermes-agent: Agent 能力 → 用 Terminal-Bench 2
- gstack: 技能质量 → 用 LLM judge
