# 03 技术架构

## 整体架构

```
用户代码 (StateGraph API)
         ↓ .compile()
CompiledStateGraph (继承 Pregel)
         ↓ .invoke() / .astream()
Pregel (执行引擎)
         ↓
PregelLoop (超步循环)
    ├── tick() → 计划超步
    │     ├── 扫描所有 Channel
    │     ├── 确定哪些节点可触发
    │     └── 构建 task 列表
    ├── 执行 tasks（可并行）
    └── commit() → 写入 Channels
         ↓
Channels (状态存储)
    ├── LastValue, BinaryOperatorAggregate, Topic...
    └── 每次超步后更新
         ↓
Checkpointer (可选持久化)
    ├── InMemorySaver, PostgresSaver...
    └── 存储 Checkpoint + Channel 状态
```

## Pregel 执行模型（Bulk Synchronous Parallel）

LangGraph 的执行引擎基于 Google Pregel 论文的 BSP 模型：

```
超步 0 (Superstep 0):
    ├── PLAN: 扫描 Channels，确定可触发节点 (node_a, node_b)
    ├── EXECUTE: 并行执行 node_a 和 node_b
    └── COMMIT: 将输出写入 Channels，生成 Checkpoint

超步 1 (Superstep 1):
    ├── PLAN: 基于新 Channel 状态，确定下一批节点
    ├── EXECUTE: 执行
    └── COMMIT: 写入

... 直到无节点可触发或达到 END
```

**关键特性**:
- 同一超步内的节点可以**并行执行**
- 超步之间有**全局同步屏障**（Barrier）
- 每个超步都可生成 **Checkpoint**（用于断点恢复）

## PregelLoop 实现

```python
# libs/langgraph/langgraph/pregel/_loop.py

class PregelLoop:
    def tick(self) -> bool:
        """执行一个超步，返回 True 表示有工作要做"""
        # 1. 从 Channels 读取状态
        # 2. 确定哪些节点有输入（触发条件）
        # 3. 构建 PregelTask 列表（每个任务=节点执行请求）
        # 4. 检查中断点 (interrupt_before/after)
        # 5. 返回 tasks

class SyncPregelLoop(PregelLoop):
    """同步版本，用于 .invoke()"""

class AsyncPregelLoop(PregelLoop):
    """异步版本，用于 .ainvoke() / .astream()"""
```

## Channel 架构

```python
# libs/langgraph/langgraph/channels/

class LastValue(BaseChannel):
    """最近写入值覆盖"""
    def update(self, values): self.value = values[-1]
    def get(self): return self.value

class BinaryOperatorAggregate(BaseChannel):
    """用二元运算符聚合（e.g., add_messages）"""
    def update(self, values):
        for v in values: self.value = self.operator(self.value, v)

class Topic(BaseChannel):
    """发布/订阅，广播给所有订阅者"""

class EphemeralValue(BaseChannel):
    """超步结束后自动清除"""
    def after_checkpoint(self): self.value = None
```

## Checkpointer 架构

```python
# libs/checkpoint/langgraph/checkpoint/base/__init__.py

@dataclass
class Checkpoint:
    v: int                           # 版本
    id: str                          # checkpoint UUID
    ts: str                          # ISO 时间戳
    pending_sends: list[SendProtocol]  # 待处理的 Send
    versions_seen: dict               # 节点已处理的版本

@dataclass
class CheckpointTuple:
    config: RunnableConfig
    checkpoint: Checkpoint
    metadata: CheckpointMetadata
    parent_config: Optional[RunnableConfig]
    pending_writes: list             # 未提交的写入

class BaseCheckpointSaver:
    def put(self, config, checkpoint, metadata, new_versions)
    def get_tuple(self, config) -> CheckpointTuple
    def list(self, config) -> Iterator[CheckpointTuple]
    def put_writes(self, config, writes, task_id)
```

## v3 Stream API（新）

```python
# 非后台线程，调用方驱动
stream = graph.stream(input, config=config, stream_mode="messages")
# GraphRunStream 是异步生成器，延迟执行
async for chunk in stream:
    # 调用方拉取时才执行下一步
    process(chunk)
```

与旧版（后台线程 + Queue）相比，v3 Stream API 是**调用方驱动**的，无后台线程，更适合异步场景。

## 技术栈

| 组件 | 技术 |
|------|------|
| **语言** | Python 3.9+ |
| **核心依赖** | langchain-core（BaseLanguageModel, BaseTool） |
| **序列化** | msgpack（Checkpoint 序列化） |
| **异步** | asyncio（AsyncPregelLoop, astream） |
| **持久化** | PostgreSQL（via psycopg3）/ Redis（via redis-py） |
| **长期记忆** | PostgreSQL vector（BaseStore） |
| **测试** | pytest + pytest-asyncio |
| **类型** | mypy strict mode |
