# 08 记忆架构

## LangGraph 的两种记忆类型

LangGraph 明确区分**短期记忆**和**长期记忆**，对应不同的存储机制。

---

## 8.1 短期记忆：Checkpointer（单线程内）

```python
from langgraph.checkpoint.postgres import PostgresSaver

checkpointer = PostgresSaver.from_conn_string(conn_str)
graph = builder.compile(checkpointer=checkpointer)

# thread_id 是会话标识
config = {"configurable": {"thread_id": "user-123-session-1"}}

# 第一轮
await graph.ainvoke({"messages": [msg1]}, config=config)

# 第二轮（自动加载之前的 messages）
await graph.ainvoke({"messages": [msg2]}, config=config)
```

**Checkpoint 存储内容:**
- 所有 Channel 的当前值（包括完整消息历史）
- 超步编号和版本信息
- 待处理的 Send() 调用

**特点:**
- 范围：**单个 thread_id 内**
- 访问方式：自动注入到状态（开发者透明）
- 存储：PostgreSQL/InMemory
- 查询：只能按 thread_id 精确查找

---

## 8.2 长期记忆：BaseStore（跨线程）

```python
from langgraph.store.postgres import PostgresStore

store = PostgresStore.from_conn_string(conn_str)

async def agent_node(state: State, config: RunnableConfig, *, store: BaseStore):
    user_id = config["configurable"]["user_id"]
    namespace = ("user", user_id, "memories")

    # 搜索相关记忆（语义搜索）
    memories = await store.asearch(
        namespace,
        query="user's preference",
        limit=5
    )

    # 写入新记忆
    await store.aput(
        namespace,
        key=str(uuid4()),
        value={"content": "User prefers dark mode", "type": "preference"}
    )
```

**特点:**
- 范围：**跨 thread_id**，可跨会话
- 命名空间结构：`(scope, user_id, memory_type)`（元组）
- 访问方式：通过 `store` 参数显式访问
- 搜索：支持语义搜索（PostgreSQL + pgvector）
- 存储：PostgreSQL 向量数据库

## 8.3 与其他项目的记忆架构对比

| 维度 | LangGraph | deer-flow | hermes-agent | nanobot | gstack |
|------|---------|-----------|--------------|---------|--------|
| **短期记忆** | Checkpointer（状态序列化） | LangGraph Checkpointer | SQLite sessions | JSON 文件 | git WIP commits |
| **长期记忆** | BaseStore（向量数据库） | MEMORY.md | SQLite facts + FTS5 | 无 | learnings.jsonl |
| **搜索能力** | 语义搜索 (pgvector) | 无 | FTS5 全文 | 无 | 关键词匹配 |
| **跨会话** | ✅ (BaseStore) | ✅ (MEMORY.md) | ✅ (SQLite) | ❌ | ✅ (JSONL) |
| **跨用户隔离** | ✅ (namespace) | ✅ (user_id 目录) | ✅ (user_id 字段) | ❌ | ✅ (project slug) |
| **记忆类型** | 开发者定义 | 事实 (Facts JSON) | 事实 + 技能 | 事实 + 概念 | 操作性知识 |
| **写入方式** | 显式代码调用 | LLM 提取 | LLM 提取 | Dream 异步 | bash 工具调用 |

## 8.4 Checkpointer 实现细节

```python
class BaseCheckpointSaver:
    def put(
        self,
        config: RunnableConfig,
        checkpoint: Checkpoint,
        metadata: CheckpointMetadata,
        new_versions: ChannelVersions,
    ) -> RunnableConfig:
        """保存检查点"""

    def get_tuple(self, config: RunnableConfig) -> Optional[CheckpointTuple]:
        """加载检查点"""

    def list(
        self,
        config: RunnableConfig,
        filter: Optional[dict] = None,
    ) -> Iterator[CheckpointTuple]:
        """列出所有检查点（用于历史回溯）"""

    def put_writes(
        self,
        config: RunnableConfig,
        writes: list[tuple[str, Any]],
        task_id: str,
    ) -> None:
        """保存节点的中间写入（用于故障恢复）"""
```

**InMemorySaver**: 线程安全的内存字典，适合开发和测试

**PostgresSaver**: 单 PostgreSQL 连接，表结构：
- `checkpoints`: 检查点主表
- `checkpoint_writes`: 中间写入（故障恢复用）
- `checkpoint_blobs`: 大对象存储

**ShallowPostgresSaver**: 只保留最近一个检查点，节省存储空间（不支持历史回溯）

## 8.5 记忆管理最佳实践

**上下文窗口管理（消息截断）:**
```python
from langchain_core.messages import trim_messages

def agent_node(state: State):
    # 截断消息，保留最近 N token
    trimmed = trim_messages(
        state["messages"],
        max_tokens=4096,
        strategy="last",
    )
    response = llm.invoke(trimmed)
    return {"messages": [response]}
```

**记忆提炼（Reflection Pattern）:**
```python
async def memory_manager(state: State, *, store: BaseStore):
    """在每轮对话后提炼记忆"""
    user_id = state["user_id"]
    recent_messages = state["messages"][-10:]

    # LLM 提炼重要信息
    insights = await llm.ainvoke([
        SystemMessage("Extract key facts about the user..."),
        *recent_messages
    ])

    await store.aput(
        ("user", user_id, "insights"),
        key=str(uuid4()),
        value={"content": insights.content}
    )
```
